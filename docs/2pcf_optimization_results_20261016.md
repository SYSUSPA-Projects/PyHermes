# 2PCF优化测试交付

新分支 `codex/2pcf-optimization` 从公开main `4280a2c` 创建，使用独立工作树。本轮完成输入准备去重和保留原核的谱空间标量归约，均为opt-in，默认旧路径。main、原图、文章和其他保护分支未改，未推送/合并。

共27个正式样本、9个J5门槛；33本地回归、真实2rank MPI的2个测试与memory策略回退验证通过。27条31bin曲线对旧结果allclose(1e-8,1e-11)，最大绝对差5.440092820663267e-15。源/输入/投影/输出SHA、32不同物理核、真实线程掩码、FFT次数与独立CSV统计均核验。

两项实现：

- `reuse_input_fields=True`：一致输入/归一化/顶点窗口才共享准备，去除重复副本、广播和delta构造；调用方数据保持不变。
- `pair_reduction="spectral"`：复用每个不同输入的rFFT与实交叉功率，用原有完整折叠核直接归约；正确保留半谱DC/Nyquist权重及N²归一化。复杂/不支持核回退旧卷积。缓存仅限单run。

图13的xi自相关路径：原31次正向＋31次逆向FFT；新8×4为8次正向、4×8为4次正向，均零逆FFT，即每rank一次，尚非全作业只做一次FFT。

首轮五组消融完整表：`performance_table.md/.csv`；J9/4×8补充见相邻验证目录的`analysis/performance_table.md/.csv`。逐次结果在两个`individual_runs.csv`，逐rank累计在`rank_phases.csv`，慢rank及计时边界说明在`profile_notes.md`。

J9旧路径的NUMA1 CPU组rank在delta/FFT中出现明显长尾，合用路径显著减轻；内存页/THP/compaction未直接测量，具体系统原因尚未唯一确定，不能把全部收益只归FFT次数。三次J9旧样本94.013/95.532/96.189s均保留；新18.291/19.645/20.101s。

本轮main的J8/8×4本身约3秒，历史17秒不能全归代码变化；跨作业或跨布局的速度不能当作严格因果比较。本轮没有重新测pycorr/TreeCorr，也不将这些CPU新值直接与历史pair-code时间排名。相同投影线程布局的epsilon SHA与旧实验逐位相同；不同线程布局的归约顺序可导致舍入级SHA差异，31bin仍按容差一致。

scaling与频谱折叠：窗口构造、scaling函数、折叠及共享卷积源文件完全未改。仍保留 K_i(k)=Σ_n A(k,n)W_i(k+nL)。任何scaling吸收/融合变换均放到最后隔离验证，未将W移到折叠求和之外，未应用未经核验的公式。
